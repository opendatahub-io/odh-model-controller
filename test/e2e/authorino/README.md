# Serverless group authorization e2e

The suite deploys real Serverless InferenceServices and InferenceGraphs on an
OpenShift cluster running KServe, Knative, OSSM and the model controller. It reads
the AuthConfigs generated by the running controller. Requests traverse the
published inference routes, Authorino, Kubernetes TokenReview and
SubjectAccessReview, and the sklearn model. Successful responses must contain the
expected predictions.

For each resource type, the same service-account token receives HTTP 403 before a
group RoleBinding, HTTP 200 after granting access, and HTTP 403 after revocation.
A binding for another resource name and a token from another namespace's group
remain denied. Missing credentials return HTTP 401. The tests bind only Group
subjects, so forwarding the username alone cannot make them pass.

The suite creates temporary namespaces and waits for their removal after each
case. Failed cases print workload, event and AuthConfig diagnostics. Tokens are
requested at runtime and are not written to reports.

## Prow

The companion `openshift/release` configuration adds the
`ci/prow/e2e-odh-kserve-auth` presubmit for `stable-2.x`. It reuses the existing
`hypershift-hostedcluster-workflow` to provision an ephemeral OpenShift cluster,
runs KServe's existing Serverless CI bootstrap with the controller image built
from the PR, then runs this suite from the PR source. The suite checks the
deployed controller image when `ODH_MODEL_CONTROLLER_IMAGE` is set.

The job runs automatically for changes matching its `run_if_changed` expression
and is required when triggered. It can also be requested with:

```text
/test e2e-odh-kserve-auth
```

Prow collects a JUnit report, Authorino/controller logs and the existing
KServe/OpenShift must-gather artifacts, then destroys the cluster. The existing
RawDeployment job remains separate.

## Running on a prepared CI cluster

Use a disposable OpenShift cluster with administrator credentials. First run
KServe's `test/scripts/openshift-ci/setup-e2e-tests.sh predictor 1 serverless`
with the intended `ODH_MODEL_CONTROLLER_IMAGE`. This installs the Serverless
stack and the `kserve-ci-e2e-test/kserve-sklearnserver` ServingRuntime used by the
suite.

From this repository, run:

```sh
bash hack/setup-authconfig-e2e.sh
make test-e2e-authorino
```

The setup script updates the operator installed by KServe's bootstrap to
Authorino Operator `v0.25.4` and creates an `Authorino` CR pinned to Authorino
`v0.26.4`. The operator owns the server Deployment, service account, RBAC and
standard Services. The script configures the mesh authorization provider and
restarts the model controller so it registers AuthConfig watches. These changes
are intended for the disposable CI cluster.

The mesh defaults to `istio-system/basic`; override `MESH_NAMESPACE` and
`CONTROL_PLANE_NAME` if the bootstrap uses different values. Go and `oc` must be
available. The `e2e` build tag excludes this suite from ordinary unit test runs.

## Headless Authorino transport prerequisite

Authorino Operator `v0.25.4` creates a headless authorization Service. OSSM 2.6
can compile that Service's upstream as `ORIGINAL_DST`, which has no original
socket destination for an Envoy-internal ext_authz call. This produces a
fail-closed HTTP 403 before Authorino receives the request, independently of RBAC.

[opendatahub-operator PR #4242](https://github.com/opendatahub-io/opendatahub-operator/pull/4242)
addresses this with a dedicated `STRICT_DNS` HTTP/2 cluster and a rewrite of the
inbound ext_authz cluster reference. The tests use the same approach in
`test/config/authconfig-e2e/envoyfilter.yaml`, pointing at the operator-created
headless Service. The filter selects only workloads labelled
`test.opendatahub.io/authconfig-groups=true`, covering both test predictors and
graphs. The setup installs it in the mesh root namespace. No additional Authorino
Service or DestinationRule is created.

The production filter in PR #4242 retains Istio mTLS, SDS credentials, SNI and
SPIFFE identity verification and includes operator capability/version gating.
This test fixture has an unmeshed Authorino pod with listener TLS disabled, so
its filter omits the TLS transport socket. The local check validates the
`STRICT_DNS` transport fix and group authorization. It does not exercise the
production mTLS configuration or the operator's filter reconciliation; see
PR #4242 for those settings and their tests.

## Local Kind transport smoke test

The Kind smoke test uses Istio `1.20.8` with headless EDS disabled, the same
operator-managed Authorino CR and EnvoyFilter, and an Istio-injected echo backend.
Disabling headless EDS reproduces the `ORIGINAL_DST` discovery behavior. The echo
Service targets an explicit inbound sidecar listener with interception mode
`NONE`, avoiding a dependency on the host's legacy iptables modules. Requests
still pass through Istio's CUSTOM authorization policy and ext_authz filter.
It renders both ISVC and InferenceGraph AuthConfig templates from this checkout.
It checks authentication, group-only access, group/resource-name isolation and
revocation. After a successful group grant, it also removes the filter and
requires HTTP 403, then restores it and requires HTTP 200 with the same token.
This separates transport failure from an RBAC denial.

This is a local transport/auth check. The full Serverless suite above exercises
controller reconciliation, Knative workloads and real model predictions in Prow.

For a fresh, disposable Kind cluster:

```sh
export KUBECONFIG=/tmp/authconfig-kind.kubeconfig
kind create cluster --name authconfig-operator-e2e --image kindest/node:v1.32.2 \
  --kubeconfig "$KUBECONFIG" --wait 120s
bash hack/setup-authconfig-kind.sh
```

Forward the test gateway in another terminal:

```sh
kubectl --kubeconfig /tmp/authconfig-kind.kubeconfig \
  --context kind-authconfig-operator-e2e -n authconfig-e2e \
  port-forward service/authconfig-gateway 15080:80
```

Then run:

```sh
KUBECONFIG=/tmp/authconfig-kind.kubeconfig \
  AUTHCONFIG_E2E_URL=http://127.0.0.1:15080 make test-e2e-authorino-kind
```

The Kind setup pins its context explicitly and rejects a different current
context in the supplied kubeconfig. The suite requires the same context; to use
a different dedicated Kind name, set `KIND_CLUSTER_NAME` for both setup and tests.
The cases run serially because the transport check temporarily removes the
shared test filter. The `e2e_kind` build tag keeps this smoke suite separate from
the Serverless suite. Go, Kind, Docker, Helm and kubectl are required. Stop the
port-forward and delete the disposable cluster after testing:

```sh
kind delete cluster --name authconfig-operator-e2e \
  --kubeconfig /tmp/authconfig-kind.kubeconfig
```
